# 複数人物 顔認識モザイク ＆ 検出通知システム (`app_mozaiku_one.py`)

OpenCV（YuNet 顔検出 ＋ SFace 顔認識）と Flask を用いた、特定人物のリアルタイム顔認識モザイク処理およびポップアップ検出通知 Web アプリケーションです。
**単一 Python ファイル構成（バックエンド API ＋ インライン HTML/CSS/JS フロントエンド）** で動作し、認識精度と出力画質を落とさずにマルチプロセス並列推論と `ffmpeg` パイプエンコードによる高速書き出しを実現しています。

画面は、プログラミングの知識がない人でも迷わず使えるよう、PC 向けの横長レイアウトと平易な日本語の表記で構成しています（詳細は「5. 画面構成と UI 仕様」）。

> **開発者 / 引き継ぎ担当者向け注記**
> 本ドキュメントは、別の開発者や生成 AI がコードベースを即座に理解し、安全に機能追加・リファクタリングを行えるよう、アーキテクチャ、データ構造、API 仕様、UI 仕様、マルチプロセス上の制約事項を網羅しています。

## 1. 主な機能一覧

1. **複数人物の登録・管理**
   - 画面右の「人物を追加」ボタンから、検出対象人物を無制限に追加・削除できます。
   - 各人物ごとに**人物名（日本語対応）**および**複数枚の顔写真**を登録できます。
2. **ドメインギャップ対策（宣材写真・角度変化への対応）**
   - **左右反転（TTA）拡張**: 登録画像ごとに「元向き」と「水平反転（`cv2.flip`）」の 2 種類の特徴ベクトルを自動生成します。
   - **動画内顔での自動補強（Boost）**: 外部写真（宣材写真など）を起点に、動画全体から最大 45 フレームをサンプリングし、最も類似度の高い動画内の本人顔を最大 5 パターン自動抽出してテンプレートへ追加します。画面上の名称は「動画から同じ顔を自動で追加」です。
   - **現在フレームからの手動追加**: プレビューで任意のシーンを停止し、映っている顔をワンクリックで特定人物のテンプレートへ追加します。画面上の名称は「今の画面の顔を追加」です。
3. **2 つの動作モード切り替え**
   - **モザイク処理 (`mosaic`)**: 登録人物「だけ」または「以外」にモザイクを適用します。モザイクの粗さ（ブロック縮小率 `4〜50`）をリアルタイムに調整できます。
   - **ポップアップ顔検出通知 (`notify`)**: モザイクをかけず、登録人物が検出された瞬間に映像右上へトースト通知（人物名・再生時間・一致度）を表示し、映像上にも日本語の人物名ラベルを描画します。
4. **チラつき防止（前後フレーム座標補間）**
   - 一瞬の横顔や遮蔽で検出が途切れた際、前後 `0〜50` フレーム（可変）の検出座標から欠損フレームのバウンディングボックスを線形補間して、モザイク・追跡を維持します。
5. **インタラクティブ・プレビュー＆高速 MP4 書き出し**
   - 動画アップロード後に自動再生します。シークバー移動、再生／一時停止、±5 秒スキップ、キーボード操作に対応し、一時停止中のパラメータ変更も即時に再描画します。
   - 書き出し時は**フル解像度・全フレーム推論**を維持したまま、キャッシュ再利用 ＋ `ProcessPoolExecutor` 並列解析 ＋ `ffmpeg` 標準入力パイプ直接エンコード（音声維持・H.264）を実行します。

## 3. 環境構築・起動方法

### 必須要件

- **Python**: 3.8 以上
- **Python パッケージ**:

  ```bash
  pip install flask opencv-python numpy Pillow
  ```

  - `opencv-python` は `cv2.FaceDetectorYN` と `cv2.FaceRecognizerSF` を含む **4.5.4 以上** が必要です。
  - `Pillow` は映像フレーム上に日本語の人物名を描画するために使用します（未インストール時は ASCII 文字列にフォールバックします）。

- **外部ツール（推奨）**:
  - **`ffmpeg`**: システム PATH に存在する場合、書き出し時に元動画の音声トラック結合と H.264 (`libx264`, `crf 18`, `veryfast`) エンコードを 1 パスで実行します。未導入環境では OpenCV の `mp4v`（音声なし）に自動フォールバックします。

### 起動コマンド

```bash
python app_mozaiku_one.py
```

起動後、ブラウザで `http://127.0.0.1:5000` にアクセスします。初回起動時のみ OpenCV Zoo から ONNX モデル（計 約 37MB）が自動ダウンロードされます。

### 推奨画面サイズ

PC のブラウザでの利用を前提にしています。**幅 1366px 以上**を推奨し、1920×1080 では、操作パネルとプレビューがスクロールなしで 1 画面に収まります。幅 1100px 以下では 1 カラム表示に切り替わりますが、主な対象ではありません。

### ネットワーク公開範囲に関する注意

`app.run(host='0.0.0.0', port=5000)` で起動するため、同じネットワーク上の他の端末からもアクセスできます。認証はありません。自分のパソコンだけで使う場合は、コード末尾の `host` を `'127.0.0.1'` に変更してください。なお、動画・写真は外部サービスへ送信されず、初回のモデルダウンロードを除き、処理はすべてローカルで完結します。

## 4. アーキテクチャと処理パイプライン

### 4.1 処理の全体フロー

1. **顔登録 (`/upload_target`, `/boost_from_video`, `/add_current_frame_face`)**:
   - YuNet で顔領域と 5 点ランドマークを検出 → `recognizer.alignCrop()` でアライメント正規化 → `recognizer.feature()` で **128 次元特徴ベクトル** を抽出します。
2. **プレビュー配信 (`/video_feed` -> `generate_frames()`)**:
   - `frame_ring_buffer` を用い、現在再生フレーム `play_idx` から未来側 `interp_gap` フレーム先まで先読みして推論結果を `state["feature_cache"]` に蓄積します。
   - 前後ウィンドウ `[play_idx - interp_gap, play_idx + interp_gap]` の評価結果から線形補間を行い、MJPEG ストリームとして配信します。
3. **動画書き出し (`/export_video` -> `export_video_worker()`)**:
   - 裏側のプレビュー再生を自動一時停止 (`state["paused"] = True`) して CPU 競合を防止します。
   - `state["feature_cache"]` に未登録のフレーム番号のみを抽出し、`ProcessPoolExecutor`（最大 8 ワーカー）で並列フル解像度推論を実行してキャッシュを補完します。
   - 全フレームの補間座標を計算後、`ffmpeg` サブプロセスの `stdin` へ生フレーム (`bgr24`) を直接パイプ送信して MP4 を生成します。
   - **書き出し映像の描画仕様**: 通知モード (`notify`) では人物名ラベル付きの枠を映像に焼き込み、モザイクモード (`mosaic`) では枠・ラベルなしのクリーンな映像を出力します。プレビューの「枠と名前を表示」(`show_debug`) の設定は書き出しには影響しません。

### 4.2 アルゴリズム仕様

- **顔照合 (`match_face_to_persons`)**:
  - コサイン類似度（`cv2.FaceRecognizerSF_FR_COSINE`）を使用します。登録済み全人物・全テンプレート（反転含む）との最大類似度が `threshold`（デフォルト `0.36`）以上の場合に一致と判定します。値が大きいほど判定はきびしくなります。
- **チラつき防止補間 (`build_interpolated_items`)**:
  - 欠損フレーム `target_idx` を挟む過去フレーム `p` と未来フレーム `n`（`n - p <= max_gap + 1`）の追跡枠ペアを探索し、以下の安全条件をすべて満たす場合のみ線形補間枠を生成します。
    1. **同一人物制約**: 両端に人物 ID がある場合、同一 ID であること。
    2. **面積比制限**: `0.45 <= area_n / area_p <= 2.2`（急激なズームや別人誤結合の防止）。
    3. **移動速度制限**: 1 フレームあたりの中心移動距離 `<= 平均顔サイズ * 0.65`（シーン切り替え時の画面横断誤補間の防止）。
    4. **重複除外**: 当該フレームで既に確定している枠との IoU が `0.35` 未満であること。

## 5. 画面構成と UI 仕様

### 5.1 レイアウト

```text
┌ ヘッダー ───────────────────────────────────────────────┐
├ 左（可変幅）──────────────────┬ 右（固定幅 420px）──────┤
│ ① 動画                         │ ② 検出したい人物         │
│  ┌ プレビュー（最大化）┐         │   人物カード（複数）      │
│  │ 未選択時はドロップ領域 │         │ ③ 処理の設定             │
│  └──────────────┘         │   動作 / 対象 / 強さ / 表示 │
│  再生ボタン・シークバー・時間   │   └ 認識の調整（折りたたみ）  │
│  検出中の人物（通知モード時）    │ ④ 書き出し（下部に固定）   │
└──────────────────────────┴───────────────────┘
```

- 画面全体は `100vh` 固定（最小高 680px）で、右パネルの ②③ の領域だけが内部スクロールします。④ 書き出しは常に最下部に表示されます。
- 動画未選択時はプレビュー領域が「ここに動画をドロップ」のドロップ領域になります。動画読み込み後は暗色のステージに切り替わり、ステージへのドロップで動画を入れ替えられます。
- トースト通知コンテナ (`#toast-container`) はプレビューのステージ内右上に配置しています。`pointer-events: none` のため、映像のクリック操作を妨げません。
- 配色はライトテーマ、アクセントは青 1 色です。色・角丸などは `:root` の CSS 変数で一元管理しています。

### 5.2 操作方法

| 操作                       | 動作                     |
| :------------------------- | :----------------------- |
| スペースキー               | 再生 / 一時停止          |
| ← / → キー                 | 5 秒戻る / 5 秒進む      |
| 映像をクリック             | 再生 / 一時停止          |
| 動画のドロップ（ステージ） | 動画の読み込み・入れ替え |
| サムネイルにマウスを重ねる | 削除ボタン（×）を表示    |

キーボードショートカットは、フォーカスが入力欄やボタン上にないとき（`event.target === document.body`）のみ有効です。

### 5.3 画面表記と内部名称の対応

非エンジニア向けに、画面上では内部名称と異なる平易な表記を使っています。コードを修正する際は、この対応を維持してください。

| 画面上の表記                               | 内部名称 / 値                                         | 補足                                                            |
| :----------------------------------------- | :---------------------------------------------------- | :-------------------------------------------------------------- |
| モザイクをかける / 画面に通知する          | `action_mode`: `mosaic` / `notify`                    | セグメントコントロール（ラジオ）                                |
| 登録した人だけ / 登録した人以外            | `mosaic_target_mode`: `target_only` / `except_target` | モザイクモード時のみ表示                                        |
| モザイクの強さ（細かい〜粗い）             | `mosaic_scale` (4〜50)                                | 大きいほど粗い                                                  |
| プレビューに枠と名前を表示する             | `show_debug`                                          | スイッチ                                                        |
| 人物を見分けるきびしさ（ゆるい〜きびしい） | `threshold` (0.20〜0.65)                              | 「認識の調整」内。大きいほどきびしい                            |
| 途切れたときの補正                         | `interp_gap` (0〜50)                                  | 「認識の調整」内。`0` は「なし」、それ以外は「Nフレーム」と表示 |
| 動画から同じ顔を自動で追加                 | `/boost_from_video`                                   | サムネイルには「自動」タグ（`source: "boost"`）                 |

### 5.4 フロントエンドが依存する要素 ID

JS は次の ID を直接参照します。HTML を改修する際は、ID を変更・削除しないでください。

- 再生系: `preview-box`, `stream-img`, `video-drop`, `video-input`, `change-video-btn`, `player-bar`, `play-pause-btn`, `seek-bar`, `time-display`, `video-status`, `status`
- 人物系: `persons-container`、および人物ごとに動的生成される `drop-<id>`, `input-<id>`, `msg-<id>`, `boost-<id>`, `cap-<id>`

- 通知・書き出し系: `toast-container`, `export-btn`, `export-card`, `export-status-text`, `export-progress-bg`, `export-progress-fill`, `manual-download-btn`

### 5.5 ユーザー向けメッセージの方針

- 人物カードの成功メッセージ（例: 「3枚の顔を追加しました」）は、**フロントエンドが登録枚数の増減から組み立てます**。サーバーが返す成功時の `message`（「パターン」「左右反転」などの技術用語を含む）は画面に表示しません。
- エラー時のみ、サーバーが返す日本語の `message` をそのまま表示します。サーバー側のエラー文言を追加・変更する場合は、専門用語を避けた平易な日本語にしてください。

## 6. グローバル状態 (`state`) データ構造

バックエンドのアプリケーション状態は単一の辞書 `state` で管理されています。スレッド間競合を防ぐため、`state_lock` および `cache_lock` を使用します。

```python
state = {
    "stream_id": str | None,         # ストリーム世代管理用UUID（新動画アップロード時に更新）
    "video_path": str | None,        # 現在の動画ファイルパス ("uploads/temp_video.mp4")
    "original_name": str,            # ダウンロードファイル名用の元ファイル名（拡張子なし）
    "total_frames": int,             # 動画の総フレーム数
    "fps": float,                    # 動画のフレームレート
    "current_frame": int,            # 現在の再生・表示フレーム番号 (0-indexed)
    "seek_frame": int | None,        # シーク要求時にセットされる目標フレーム番号
    "paused": bool,                  # 一時停止フラグ
    "settings_dirty": bool,          # 一時停止中の設定変更を検知して再描画するフラグ

    # 複数人物管理リスト
    "persons": [
        {
            "id": str,               # 人物UUID
            "name": str,             # 人物名（UI表示・映像ラベル・通知用）
            "entries": [
                {
                    "id": str,       # テンプレート画像UUID
                    "crop_b64": str, # サムネイル表示用Base64 JPEG
                    "source": str,   # "photo" (手動登録) | "boost" (動画抽出)
                    "vectors": [np.ndarray, np.ndarray] # [元向き128次元, 左右反転128次元]
                }
            ]
        }
    ],

    "action_mode": str,              # "mosaic" | "notify"
    "mosaic_target_mode": str,       # "target_only" | "except_target"
    "mosaic_scale": int,             # モザイク縮小率 (4〜50、大きいほど粗い)
    "threshold": float,              # コサイン類似度閾値 (0.20〜0.65)
    "interp_gap": int,               # チラつき防止補間の最大フレーム幅 (0〜50)
    "show_debug": bool,              # プレビュー時の枠・ラベル描画ON/OFF

    "latest_detections": [           # /progress ポーリングでフロントに返す現在フレーム検出人物
        {"id": str, "name": str, "score": float}
    ],

    # 推論結果キャッシュ: { frame_idx (int): [(x, y, w, h, feat_ndarray), ...] }
    "feature_cache": dict,

    # 書き出し進捗状態
    "export_status": str,            # "idle" | "processing" | "done" | "error"
    "export_progress": int,          # 0〜100
    "export_message": str,           # UI進捗表示テキスト
    "output_path": str | None        # 書き出し完了ファイルパス
}
```

## 8. 改修・機能追加を行う際の重要制約

別の開発者や生成 AI に本コードの修正を依頼する際は、以下の実装制約を必ず維持してください。

### 8.1 バックエンド・推論

1. **Windows におけるマルチプロセス制約 (`ProcessPoolExecutor`)**
   - Windows 環境では `multiprocessing` が `spawn` 方式で起動されるため、ワーカー関数 `analyze_video_chunk()` は必ず**モジュールのトップレベル**に定義する必要があります（関数内ネストや `lambda` は `PicklingError` になります）。
   - `cv2.FaceDetectorYN` や `cv2.FaceRecognizerSF` のインスタンスは C++ バインディングであり pickle 化できないため、プロセス間で渡さずワーカー関数内で都度 `create()` してください。
2. **推論精度・画質の維持**
   - `analyze_video_chunk` および `generate_frames` では、顔認識精度を担保するため**フレームを縮小せず元解像度のまま**推論を行っています。高速化のために推論用フレームをリサイズする変更は、ユーザーから明示的な許可がない限り行わないでください。
3. **キャッシュの整合性**
   - `state["feature_cache"]` は「モデルの生出力（顔座標と 128 次元ベクトル）」のみを保持しており、閾値 (`threshold`) やモード (`action_mode`, `mosaic_target_mode`) に依存する判定結果はキャッシュしていません。そのため、**新しい動画がアップロードされた時のみキャッシュを破棄**し、設定変更時はキャッシュを破棄せず再評価のみ行う設計を維持してください。
4. **日本語描画の互換性**
   - OpenCV 標準の `cv2.putText` は日本語を描画できません（`???` に文字化けします）。映像上に人物名を描画する際は `draw_boxes_and_labels()` のように `Pillow` (`ImageDraw`) へ変換して描画する方式を維持してください。

### 8.2 フロントエンド・HTML テンプレート

5. **`render_template_string` との衝突を避ける**
   - `HTML_TEMPLATE` は Flask の `render_template_string`（Jinja2）で処理されます。テンプレート内の CSS / JS に **`{{`、`{%`、`{#`** を含めると Jinja2 の構文として解釈され、エラーや表示崩れの原因になります。JS のテンプレートリテラル（`${...}`）は問題ありませんが、オブジェクトを二重の波括弧で書かないよう注意してください。
   - `HTML_TEMPLATE` は通常の（raw ではない）Python 三連引用符文字列です。そのため、テンプレート内に **バックスラッシュ（`\n` など）や `"""`** を書かないでください。改行や特殊文字が意図せず変換されます。
6. **ポップアップ通知のスパム防止**
   - フロントエンドの `startProgressPolling()` では 250ms ごとに `/progress` をポーリングしています。毎フレーム通知が出続けるのを防ぐため、人物 ID ごとのクールダウン制御（`POPUP_COOLDOWN_MS = 4000`）をフロントエンド側で維持してください。
7. **要素 ID と画面表記の維持**
   - 「5.4 フロントエンドが依存する要素 ID」の ID は変更しないでください。また、「5.3 画面表記と内部名称の対応」の平易な表記を、専門用語（閾値、補間、Boost など）へ戻さないでください。
8. **改行コード**
   - `app_mozaiku_one.py` は全行 CRLF で統一されています。編集後も CRLF を維持してください。

## 9. 既知の制限事項と今後の拡張候補

### 既知の制限事項

- **単一セッション設計**: サーバー側のグローバル辞書 `state` と固定ファイルパス（`uploads/temp_video.mp4`）を使用しているため、複数ブラウザタブや複数ユーザーからの同時アクセスには対応していません（マルチユーザー化する場合はセッション ID ごとのディレクトリと状態管理テーブルへの分離が必要です）。
- **ダウンロード名**: `/download_video` のファイル名の接尾辞（`_mosaic` / `_notify`）は、書き出し時ではなくダウンロード時点の `action_mode` で決まります。書き出し後にモードを切り替えると、名称が実際の内容と逆になることがあります。
- **ffmpeg のエラー**: ffmpeg の標準エラー出力は `DEVNULL` に捨てているため、エンコード失敗時の原因が画面に表示されません。
- **ページ再読み込み**: ブラウザを再読み込みしても、サーバー側の動画・人物登録は残りますが、画面は動画未選択の状態に戻ります。設定値は起動時に画面の状態でサーバー側を上書きします。

### 拡張アイデア

- **人物ごとの個別アクション設定**: 「人物 A はモザイク、人物 B は通知のみ、未登録者はモザイク」といった人物単位のルール設定。
- **シークバー上の検出タイムライン表示**: `feature_cache` を利用した登場シーンのヒートマップ表示とシーンジャンプ機能。
- **モザイク以外のエフェクト**: ガウスぼかし（`cv2.GaussianBlur`）やカスタム PNG 画像（スタンプ）のオーバーレイ対応。
